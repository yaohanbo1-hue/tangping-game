# 运行时、音频与实战统计改进

2026-11-07建立、2026-11-08续作，本地开发记录，当前文件版本2.0.0，未提交／推送／发布。当前剩余范围见 [执行计划](COMPLETION_PLAN.md)。

## 测量驱动的战场优化

`tests/profile-battlefield.js` 固定 32 座 Lv12 建筑和 95 个敌人。静态场景包含混合怪物与光束；动态场景使用高生命 grunt/swarm，按每帧一个真实 1/60 秒模拟步推进。资源／生命是压力夹具，不能作为平衡通关证据。每组暖机45帧、采样150帧，分别测模拟、绘制子步骤、HUD 与帧间隔；嵌套计时不能相加。

本机 Windows / Chromium153 / headless / 1440×900 软件渲染，对照关闭指定绘制：

| 动态场景 | 平均帧间隔 ms | P95 ms |
|---|---:|---:|
| 完整低画质、旧飘字绘制 | 150.91 | 227.3 |
| 仅关闭飘字 | 19.33 | 24.4 |
| 仅关闭粒子与光束 | 157.09 | 233.6 |
| 仅关闭敌人受击叠画 | 167.84 | 250.0 |
| 仅关闭HUD更新 | 153.38 | 236.9 |

主要瓶颈是不断缩放、重复描边的文字栅格化／合成。`text-art.js` 改为离屏缓存字形，移动／缩放／透明度仍按原动画推进；长提示换行。缓存同时限制128项与8MiB，热缓存不重复画字，不改变结算。场景和机械主体本来已有缓存；模拟平均约0.75–0.78ms，范围查询不是这组压力夹具的主要瓶颈，本轮没有凭猜测引入空间索引。

加入低／中／高三档：粒子64／200／600上限、光束20／64／160预算、不同光晕与天气；保留敌人、血条、状态、攻击提示。诅咒等承担伤害逻辑的区域不受视觉预算裁剪。首页及游戏内图鉴／设置均能切换并保存。

## 表现随机数与奖励

`presentation.js` 给粒子、音频、界面分配独立 PRNG；旧粒子生成概率、飘字偏移、角色摆动、聊天位置与音效噪声均不再读取战斗随机数。随机暴击、掉落、分裂位置、波次与奖励仍使用战斗随机源。切换画质／静音不会改变未来战斗结果，但拆分前后的同一测试种子不承诺复现旧序列。

`tests/presentation.test.js` 在三档画质×音效开关的六种组合下，逐秒比较完整战斗状态、实际伤害、资源、掉落和后续随机值。另检查硬预算、诅咒结算与设置恢复。

隐藏旋律改为发现时立即兑现奖励，音符单独调度；新局清空旋律与点击历史，旧局音符不串入下一局。赠礼纳入战中存档账本，发现后立刻保存／读取不会丢奖励，已发现旋律不会再次支付。

## 音频分组与验收

`audio.js` 拆出合成音效：主音量控制音乐及音效，音效再分战斗／界面／环境组，采用平方振幅曲线、短起音包络与动态限幅。全局24声部，分组16／6／1上限；同类武器节流，噪声复用一份缓冲。11种攻击来源使用不同音高、波形、滑音、噪声或双音组合。剧情压低音乐只改变 duck，不覆盖玩家音量；后台停止音效并压低音乐，返回保留用户设置。

首页和战斗内设置同步；原生手机滑杆／选择框有44px操作高度。

`tests/audio.browser.test.js`在真实Chromium AudioContext验证手势解锁，在OfflineAudioContext渲染11种武器、五Boss预警、分组／主／后台静音与混音：

- 11武器与五Boss共16种输出均非静音、没有NaN／削波，尾音按预定时间释放；11武器和五Boss分别有不同波形签名。Boss预警峰值约0.121—0.152。
- 1000次噪声请求与界面／环境叠加时，实际最高23声部，缓冲仅1份；混音峰值0.258，结束节点清理。
- 连续60秒离线音频、每秒40次请求，战斗峰值16，结束活动节点0，缓冲仍为1。
- 57%音乐音量在剧情压低与设置保存后仍为57%；关闭效果不污染战斗随机数。
- 试听文件：`artifacts/audio/chromium-weapon-sampler.wav`，先turret、frost、laser、tesla、flame、poison、sonic、missile、gravity、prism、generator，再lord、abyss、machine、void、final预警，每项1秒，共16秒。PCM验证不能替代实际扬声器／耳机听感评价。

本机 Windows WebKit26.6 实测不提供 AudioContext 或 OfflineAudioContext；测试明确记录 `unsupported-web-audio`，只验收设置与无音效时继续操作，没有把音频跳过写成Safari声音通过。浏览器平台功能可能不同，参见 [Playwright官方浏览器说明](https://playwright.dev/docs/browsers#webkit)。真实Safari解锁／出声仍待物理iPhone验收。

## 实战贡献统计（逻辑与实际浏览器已验证）

`telemetry.js` 从统一伤害结算入口记录实际本体／护盾损失，过量、阶段免伤、无效伤害不记入。单座建筑近5模拟秒DPS以0.1秒桶采样，空闲计零；50桶固定内存，不保存到游戏状态。理论DPS继续保留，实测值随目标抗性、毒层、穿透与反应自然变化。

矿机和发电机累计真实产出，矿机按当前收益估算账面回本；银行按当前存款、生产上限与全体银行份额给出波末预计收益，并记录实际结算。维修只记录实际恢复，护盾重叠按最高容量来源归属、吸收不重复计量。增幅器显示覆盖数量与投入分摊，电量、修复和护盾不虚构金币回本或攻击DPS。全部观察在开始／载入时重置，不改变存档格式或战斗随机数。

新增27项统计逻辑，真实浏览器验证实际50点结算显示10DPS、空闲衰减到0、焦点与滚动保持。11条合法战役已完成，最终状态见V2_STATUS.md。

## 最终精修后的固定场景采样

2026-11-08，`node tests/profile-battlefield.js --label=final --debug`。每组在同一种子下重新创建一局，再设置32座建筑／95敌人，避免点击开始后已推进的少量实时帧进入初始经济／统计。45帧暖机＋150帧采样，主动模拟每帧1/60秒；浏览器为本机Windows／Chromium153，1440×900无头软件渲染。

| 主动模拟画质 | 平均帧间隔ms | P95ms | 模拟均值ms | 绘制均值ms |
|---|---:|---:|---:|---:|
| 低 | 16.67 | 17.80 | 0.67 | 2.48 |
| 中 | 23.55 | 33.20 | 0.75 | 2.45 |
| 高 | 28.05 | 39.20 | 0.75 | 2.70 |

三个最终战斗摘要均为 `9c6b558247d18bea7c509de5f7b489db1ff7212f00f11fda3176d9c69ea20d39`。原始分项与结束状态保存在 `artifacts/runtime-profile-final.json`。这里只比较同一最终夹具的三档画质，不拿后续数值／美术变化后的样本与旧夹具直接算提升倍数，也不把JS绘制耗时当作完整帧间隔。

最终经典流程的另一组180帧压力回归：桌面平均22.78ms／P95 49.90ms、Android仿真22.79ms／33.40ms、Windows WebKit仿真115.07ms／185ms，结束敌人数89／79／60。因实体演进与实际模拟时长不同，仅记录各自表现，不用于新旧加速比。尤其WebKit仍明显超出流畅帧预算，不能声称所有浏览器满场流畅；物理设备仍须通过验收页实际采样。原始结果为 `artifacts/browser/frame-times.json`。

WebKit追加单引擎排查：其相同摘要的低档完整／关闭文字夹具分别为平均58.28／75.13ms，而JS绘制为7.73／2.69ms。去掉文字降低绘制CPU开销，没有改善完整帧间隔，说明完整等待还涉及该平台的软件合成／调度，不能只用JS计时归因。

低画质进一步采用1×字形、固定尺度／整数位置并停止震动；中／高保留1.5×／2×字形与原有动画。WebKit低档本次采样平均70.95ms、P95 95ms，绘制8.32ms；字形实际像素用量约2.18MiB。这轮只确认有界内存与减少动态，没有把它宣称为WebKit帧率提升。报告为 `runtime-profile-webkit-low-aligned.json`；跨样本战斗摘要不同，未作严格加速比。

最后补上陨石模拟时钟回归：旧实现暂停后墙上时钟仍落伤，新实现只随 `updateEffects` 推进，暂停／后台不结算；重开／读档自然丢弃旧弹道，目标死亡／离场和Boss阶段护甲都有检查。14项新增检查通过；合法战役重新按最终代码生成。
